Good tools become better
when they can talk.

Mac apps are wonderfully focused. But a workflow rarely ends at one app’s window.

Talk was built so independently developed apps can cooperate through a clear, shared contract. Less one-off integration plumbing. More time for the things your app does best.

One SDK. Local communication. The user in control.

One app. Either side
of the conversation.

An app can offer actions, run actions in other apps, or do both. Each direction has its own connections and permissions.

Let apps use yours.

Define what your app can do. Publish its contract. Other developers can build against it without you adding custom code for every new app.

Explore the pairing flow
  1. 1

    Find the right app.

    Turn on pairing in the app offering actions. Discover it from the supported app library in the app that will use them.

  2. 2

    Compare. Choose. Approve.

    Compare the full code in both apps. Review the permissions and approve only the access you want to give.

  3. 3

    Keep your workflow moving.

    Later permitted actions use the saved grant. Revoke access per integration. New permissions need new consent.

A public beta, still growing

Build with a clear
understanding of the limits.

Talk needs more testing and validation before production reliance. APIs may change. Start with synthetic or noncritical data and validate your actual signed apps.

* Targets macOS 12.4+; Monterey runtime validation is pending. Swift 6.2+ and correctly Apple-signed, provisioned app targets are required for saved pairing.

Pairing proves possession of a paired credential. App names are not verified publisher identities. Broader platform, distribution, and independent security qualification remain open.
